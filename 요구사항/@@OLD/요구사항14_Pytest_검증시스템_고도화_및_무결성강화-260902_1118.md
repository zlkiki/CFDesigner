# 요구사항 14: Pytest 검증 시스템 고도화 및 무결성 강화 (Master)

## 1. 목적 및 배경 (Background & Objectives)

본 요구사항은 CFDesigner 프로젝트에서 **"Pytest 단위 테스트(86개)를 100% 통과함에도 불구하고 실제 브라우저/런타임에서 기능 결함 및 크래시가 발생하는 문제"**를 근본적으로 해결하기 위해, 테스트 스위트의 신뢰도와 결함 검출력을 비약적으로 끌어올리는 **5대 무결성 고도화 체계**를 구축하는 것을 목적으로 합니다.

### 1.1 기존 테스트 체계의 5대 구조적 맹점
1. **프론트엔드 JS 런타임/정적 무결성 검증 부재**: `viewer_3d.js`의 `buildStressProfile()` 미정의와 같은 JS `TypeError` 크래시를 백엔드 pytest가 전혀 감지하지 못함.
2. **느슨한 API 스키마 검증**: HTTP 200과 단순 키 유무만 검사하여 `/api/fsm/parameters`의 필수 서브필드(`mode_lfs`, `nodes`, `strips`) 결측을 통과시킴.
3. **수치해석 물리적 유효성(Sanity Check) 부재**: 휨 상태 긴 반파장에서의 $O(L^2)$ 막 변형 발산($M_{cr3} \sim 1.7 \times 10^6$) 및 Chart.js Y축 스케일 왜곡을 `assert > 0`의 느슨한 단언문으로 통과시킴.
4. **변수 오대입 통과**: `test_dxf_integration.py`에서 휨 설계 입력(`m_cre`)에 모멘트가 아닌 압축하중(`p_cre`)을 넣었음에도 양수 조건으로 인해 합격 처리됨.
5. **다단계 사용자 상태 전이(Stateful Workflow) 검증 부재**: "단면 생성 $\rightarrow$ 휨 응력 선택 $\rightarrow$ 도심 정렬" 시 응력 상태가 압축으로 리셋되는 상태 머신 결함 검출 실패.

## 3. 종합 검증 기준 (Acceptance Criteria)

- [x] **AC 14-1 [API 스키마 무결성]**: `/api/section/wizard`, `/api/fsm/solve`, `/api/fsm/parameters`, `/api/design/check`, `/api/report/html` 전 엔드포인트의 반환 데이터가 Pydantic 모델과 100% 일치하며 결측/타입 오류 0건일 것.
- [x] **AC 14-2 [수치해석 Sanity]**: 5종 단면 $\times$ 5종 하중 $\times$ 50스텝 스윕에서 NaN, Inf, 차수 역전이 없으며 긴 반파장 휨 상태에서 $O(L^2)$ 발산값이 $\lambda \le 25\lambda_1$ 이내로 완벽 필터링될 것.
- [x] **AC 14-3 [상태 전이 E2E]**: 단면 변경 $\rightarrow$ 휨 FSM $\rightarrow$ 도심 정렬 $\rightarrow$ KDS 부재설계 $\rightarrow$ 계산서 출력의 다단계 상태 전이에서 응력 상태 유실 없이 데이터가 온전히 계승될 것.
- [x] **AC 14-4 [프론트엔드 정적 무결성]**: `index.html` 내의 모든 DOM ID와 JS 바인딩이 1:1 일치하고, `app.js`에서 호출하는 모든 컴포넌트 메서드가 대상 JS 파일에 실재할 것.
- [x] **AC 14-5 [단언문 리팩토링 & 100% Pass]**: `test_dxf_integration.py`의 파라미터 오대입이 수정되고, 전체 고도화된 pytest 스위트(100+ tests)가 100% 통과할 것.
